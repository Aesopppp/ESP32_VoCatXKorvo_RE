# 统一全双工语音会话

2026-11-18，ESP32_VoCatXKorvo。按用户与平台确认实施，沿用 C 服务结构、ESP-IDF 6.1、Opus 与现有 VoCat 音频驱动。

## 当前规则

- 用户或 MQTT 唤醒后建立 WebSocket，通过 `__proxy_connected__` 鉴权通知后连续上传 AEC 后的麦克风音频。
- 同一连接内 AI 回复、电话和提醒统一接收、解码、播放。16 kHz 单声道，上行 20 ms Opus Base64 JSON，下行一条 binary 消息一个完整 raw Opus 包，未改为 PCM/Ogg。
- 不需要 `speech_started` / `speech_stopped` / `response.audio.done` / `response.output_audio.done` / `response.done`。这些事件即使出现也不改变收发状态。
- 不发送 `response.cancel` / `input_audio_buffer.commit` / `response.create`。平台决定停止生成/发送及提醒优先级；设备不按人声清缓存，平台停发后已有缓存自然播完。
- 无音频只是暂时无输出，仍可继续接新音频。首页轻触结束或双向连续 60 秒无有效语音时关闭 WebSocket；平台把关闭视为挂断。MQTT 待机常连。
- 用户主动挂断及真实网络/输出故障仍可清理本次会话缓存，旧连接音频不得进入新连接。

## 有效语音与界面

静默计时由 `session_policy.h` 统一计算，不依赖服务端断句事件，也不因播放状态暂停计时：

- 上行：AFE 的 VAD 判为语音且 PCM 均方能量达到已有阈值 2500，在采集时记录活动时间。
- 下行：实际输出、硬件音量增益前的 PCM，平均绝对幅度至少 64 且持续 40 ms 后更新活动时间。阈值集中在 `pcm_policy.h`。
- 任一方向有效活动均续会话。连续静音包、心跳、MQTT 状态报告、控制事件不能续期；音量为零不影响接收方向的活动判断。
- 下行是幅度活动近似，不是语言内容识别；持续背景声音可能保持会话，过弱音频可能未被判为活动，需要实板核对阈值。
- 聆听/播放仅描述界面，切换不启停上传。下行活动保留 250 ms 的显示窗口，避免音节间隙频繁闪动。
- 保持现有 UI 的音频优先刷新策略，本次未增加动画负载。

## 播放缓存与退出

PCM 预填 300 ms、容量 500 ms、DMA 约 60 ms；网络消息队列保留既有有界上限。
没有 EOF 的短音频等待不超过 300 ms 即可起播，尾部继续输出，不滞留到下一句话。
缓存全播意味着平台停止发送后可能仍有尾音；实际延迟取决于已接收的网络和 PCM 积压，不能仅以 300 ms 预填估算上限。
超出队列上限的输入记录丢弃诊断，不无限分配内存。

取消旧回复的镜像状态、回合接收门禁、等待回复/播放完成超时与提醒专用播放器生命周期已移除。
保留认证/传输失败恢复、连接代次隔离、分片重组、缓存上限、上传失败检查。
退出先停上传并关闭连接；停止失败则等待清理，不清空仍由上传任务使用的 FIFO，不允许新会话抢用。
真实连接恢复最多等待 60 秒；自动提醒最终失败保留通知，等待用户唤醒、网络恢复或新通知再交接。

## MQTT 提醒

详见 [MQTT 接入](device-mqtt.md)：

1. 待机收到任务：保存编号，唤醒、建连，沿用首帧 auth 的 `device_id/api_key/task_ids`。认证后即开始双向音频。
2. 在线收到任务：平台直接推音频；设备不发送额外任务请求、不重复 auth、不重连。
3. 提醒可被平台语音打断，之后保持同一连接继续对话。
4. 设备仅维护待交接通知，不判断完整播报、不发送 `audio_received` 业务回执、不按已播历史去重；MQTT 协议 PUBACK 保留。
5. 保留紧凑 NVS 兼容读取、设备身份隔离和待处理任务 ID，不改分区、不擦除 NVS。

## 回归与实板验收

`python scripts/check_audio.py --cc <TCC路径>` 覆盖生产连续 PCM、上传、WS 分块/鉴权/代次、可选事件后继续收音频、双向静默/时钟回绕、任务唤醒与触屏退出。
`check_device_mqtt.py` 覆盖任务保存/交接/重启/失败暂停；`check_device_auth.py` 和 `check_handshake.py` 覆盖原有凭据流程。

主机测试和编译不能证明真实扬声器听感、AEC 双讲效果与网络稳定性。烧录后至少验证：

1. 无任何 speech/response 事件时，短回复和两分钟以上长音频均可播放。
2. 同时讲话与听对方声音；平台停发时尾音播完，没有 cancel 或事件触发重连。
3. 持续远端语音/持续本机说话超过 60 秒保持连接；双向静音满 60 秒退出，连续静音包不能阻止退出。
4. 待机提醒唤醒后可说话打断；在线提醒插播不重连，结束后继续对话。
5. 首页在连接、监听、播放阶段轻触均能结束，菜单调节不挂断。
6. 断网/重连、重复任务和重启后无自动唤醒循环；MQTT 始终不发送播放结果 ACK。
